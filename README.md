# TOWNTEAM Window Setup — GitHub Pages

## النشر
1. أنشئ Repository في GitHub باسم window-setup.
2. ارفع محتويات هذا المجلد في جذر المستودع، وليس ملف ZIP نفسه.
3. Settings → Pages → Deploy from a branch → main → /(root) → Save.
4. انسخ الرابط الذي يظهر في Pages.

## حالة النسخة
تم تعديل مسارات الملفات والاتصال لتناسب GitHub Pages. لا تحتاج npm أو build.
الخدمة الحالية تحتاج إعداد CORS للعنوان الجديد قبل عمل تسجيل الدخول ورفع وعرض الصور بالكامل. لم يتم تعديل الخدمة الحالية، ولم يتم اختبار الدخول بحساب فعلي. لا توزع الرابط على الفريق قبل اختبار رفع الصور والمراجعة بحساب VM وحساب الإدارة.

الجلسة في الذاكرة فقط: عند إعادة تحميل الصفحة، سجّل الدخول مرة أخرى. الصور والبيانات تبقى في الخدمة المشتركة وليست في المتصفح.
لا ترفع كلمات مرور أو مفاتيح service_role في المستودع. المفتاح الموجود في connection.js مفتاح publishable مخصص للواجهة.

## تصدير Window Display (2026-10-29)
- زران بعد تسجيل الدخول: تصدير PowerPoint وتصدير PDF.
- النافذة تعرض نطاق الفروع حسب البيانات المسموح بها من الخدمة. خيار الشركة بالكامل للمراجع فقط، والفلترة متاحة للجميع ضمن صلاحياتهم.
- أحدث صورة في كل موضع فقط، شريحة مستقلة لكل صورة بعنوان الفرع، وغلاف وخاتمة.
- ملف PPTX يحفظ العناوين كنصوص أصلية والصور كعناصر منفصلة يمكن تغييرها وتحريكها. الديكور خلفية واحدة.
- بيانات اسم الـVM والمنطقة قابلة للمراجعة قبل التصدير. غلاف الشركة VM TEAM / WINDOW DISPLAY / ALL BRANCHES.
- لا توجد خدمة جديدة ولا مفاتيح إضافية: الصور تُقرأ بواسطة wsFetch الحالي مع الجلسة والصلاحيات نفسها.
- مكتبات التصدير محلية في vendor، تُحمّل فقط عند الضغط على التصدير. يحتفظ كل ملف بإشعار ترخيصه.
- ينتظر تحميل كل الصور بنجاح قبل تنزيل الملف؛ فشل تحميل أي صورة يعرض خطأ ويتيح إعادة المحاولة، دون تنزيل ملف ناقص.
- الفروع بدون صور تُذكر في عدد منفصل قبل التصدير ولا تحصل على شرائح فارغة.
- البيانات التجريبية فقط اختُبرت في المتصفح. يجب بعد النشر تجربة حساب VM وحساب مراجع وصور خاصة فعلية، للتأكد من صلاحيات الخدمة والنشر.
